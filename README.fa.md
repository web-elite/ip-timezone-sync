# همگام‌سازی منطقه زمانی IP (IP Timezone Sync)

[English](README.md)

افزونه‌ای مبتنی بر Manifest V3 برای مرورگرهای Chromium که منطقه زمانی IANA مرتبط با IP عمومی را تشخیص می‌دهد و آن را روی بخشی از APIهای جاوااسکریپت `Intl` و `Date` در صفحه اعمال می‌کند.

> **سطح پیش‌فرض: سطح ۱ (سبک).** این سطح برای کمترین فشار پردازشی طراحی شده است. سطوح بالاتر APIهای بیشتری را تغییر می‌دهند و ممکن است هزینه پردازشی و ریسک ناسازگاری بیشتری داشته باشند.

## امکانات

- تشخیص منطقه زمانی IP عمومی با استفاده از [ipwho.is](https://ipwho.is/) و سرویس جایگزین [ipapi.co](https://ipapi.co/).
- به‌روزرسانی دستی، هنگام اجرای مرورگر، هنگام باز شدن تب جدید، هر یک ساعت یا هر شش ساعت.
- چهار سطح قابل تنظیم برای میزان هماهنگ‌سازی APIهای زمان.
- حفظ مقدار صریح `timeZone` که خود وب‌سایت به `Intl.DateTimeFormat` می‌دهد.
- اجرای کد صفحه در زمان `document_start` و فقط در فریم اصلی صفحه.
- استفاده از کش محدود برای Formatterها و کاهش تعداد محاسبات اختلاف ساعت.

برای تغییر سطح، وارد بخش **Settings** افزونه شو، سطح موردنظر را انتخاب کن و روی **Save settings** بزن. با تغییر سطح، تب‌های باز HTTP(S) دوباره بارگذاری می‌شوند تا پروفایل جدید به‌درستی اعمال شود. سطح پیش‌فرض ۱ است.

**پیشنهاد انتخاب سطح:** برای وب‌گردی روزمره و کمترین مصرف منابع از سطح ۱ استفاده کن. فقط در سایت‌هایی که به هماهنگی بیشتری بین Date و Intl نیاز دارند سطح را افزایش بده. سطح ۴ برای تست‌های سخت‌گیرانه‌تر است و پیشنهاد نمی‌شود به‌صورت پیش‌فرض برای همه سایت‌ها فعال باشد.

## نصب

۱. مخزن را به‌صورت ZIP دانلود و Extract کن یا با Git کلون کن:

```bash
git clone https://github.com/web-elite/ip-timezone-sync.git
```

۲. در Chrome آدرس `chrome://extensions` را باز کن. در Edge یا Brave نیز صفحه مدیریت افزونه‌ها را باز کن.

۳. گزینه **Developer mode** را فعال کن.

۴. روی **Load unpacked** بزن و پوشه پروژه را انتخاب کن.

۵. وارد بخش **Settings** افزونه شو و سطح محافظت و زمان‌بندی بررسی IP را تنظیم کن.

## زمان‌بندی بررسی IP

- **New tab:** هنگام ایجاد تب جدید، IP بررسی می‌شود.
- **Browser startup:** هنگام اجرای مرورگر بررسی انجام می‌شود.
- **Every 1 hour / 6 hours:** بررسی دوره‌ای هر یک یا شش ساعت.
- **Manual only:** فقط با زدن دکمه **Check IP now** بررسی انجام می‌شود.

درخواست تشخیص IP از Service Worker افزونه ارسال می‌شود. این درخواست معمولاً از Proxy تنظیم‌شده در مرورگر یا VPN سیستمی استفاده می‌کند؛ اما پراکسی‌ای که فقط داخل یک برنامه دیگر تنظیم شده باشد، لزوماً روی این درخواست اثر نمی‌گذارد.

## سازوکار عملکرد

افزونه از سرویس تشخیص IP می‌پرسد منطقه زمانی مرتبط با IP عمومی‌ای که درخواست از طریق آن دیده می‌شود چیست. سپس شناسه منطقه زمانی IANA (برای مثال `Europe/Stockholm`) را به Shim جاوااسکریپت صفحه می‌فرستد.

کد صفحه در زمان `document_start` تزریق می‌شود، اما Bridge در محیط ایزوله تنظیمات ذخیره‌شده را به‌صورت غیرهم‌زمان دریافت می‌کند. بنابراین ممکن است اسکریپتی که خیلی زود در صفحه اجرا می‌شود، قبل از دریافت منطقه زمانی جدید، منطقه زمانی مرورگر را ببیند. سازوکار Handshake این تأخیر را کاهش می‌دهد، اما تضمین نمی‌کند که تمام اسکریپت‌های سایت منتظر دریافت تنظیمات بمانند.

## حریم خصوصی

- افزونه برای تشخیص منطقه زمانی به ipwho.is درخواست می‌فرستد و در صورت نیاز از ipapi.co به‌عنوان جایگزین استفاده می‌کند.
- این سرویس‌ها IP عمومی استفاده‌شده برای درخواست را دریافت می‌کنند.
- IP درخواست ممکن است با IP یک Proxy مخصوص تب، افزونه VPN یا تونل سطح برنامه متفاوت باشد.
- مکان‌یابی بر اساس IP تقریبی است؛ منطقه زمانی بازگشتی، تخمین سرویس‌دهنده برای IP عمومی است و موقعیت دقیق دستگاه محسوب نمی‌شود.

## محدودیت‌ها و سازگاری

- این افزونه منطقه زمانی سیستم‌عامل یا منطقه زمانی native پروفایل مرورگر را تغییر نمی‌دهد.
- Shim فقط APIهای مشخصی از جاوااسکریپت را در فریم اصلی صفحه تغییر می‌دهد و محیط Worker، SharedWorker یا Service Worker را بازنویسی نمی‌کند.
- فریم‌های فرزند عمداً از تزریق افزونه مستثنا هستند؛ Content Script فقط در فریم اصلی اجرا می‌شود.
- APIهای native مرورگر، Workerها، Service Workerها، اجرای بسیار زودهنگام اسکریپت‌ها و رفتار صریح وب‌سایت ممکن است اختلاف منطقه زمانی را آشکار کنند.
- تغییر Built-inهای جاوااسکریپت قابل مشاهده و شناسایی است. این پروژه تضمین Stealth، مقاومت در برابر Fingerprinting یا عبور از سیستم‌های تشخیص تقلب نمی‌دهد.
- سطوح بالاتر APIهای بیشتری را تغییر می‌دهند و ممکن است مصرف CPU را افزایش دهند، به لبه‌های ناسازگاری برخورد کنند یا اجرای اسکریپت بعضی سایت‌ها را مختل کنند. اگر سایتی درست کار نکرد، به سطح ۱ برگرد.

## تست‌ها

برای اجرای تست‌ها به Node.js نسخه ۲۲ یا جدیدتر نیاز داری:

```bash
node tests/timezone.test.cjs
node tests/historical-zones.test.cjs
```

تست‌ها رفتار سطوح مختلف، parsing و ساخت Date، Getterها و Setterهای محلی، حفظ timezone صریح، ثابت‌ماندن رفتار UTC، تغییر منطقه زمانی، تغییر ساعت تابستانی (DST) و رفت‌وبرگشت تاریخی `Intl.DateTimeFormat` به `Date` را در منطقه‌های زمانی پشتیبانی‌شده IANA بررسی می‌کنند.

این‌ها تست‌های رفتاری مبتنی بر Node.js هستند و جای تست واقعی افزونه در Chromium و سایت‌های هدف را نمی‌گیرند.

## نکات عملکردی

- Content Script فقط در فریم اصلی اجرا می‌شود تا در سایت‌های دارای iframeهای زیاد، پردازش چندبرابر نشود.
- نمونه‌های `Intl.DateTimeFormat` در کش LRU محدود به ۳۲ مورد نگهداری می‌شوند.
- تبدیل زمان محلی به‌جای اسکن ۳۳ زمان، سه اختلاف ساعت نزدیک را بررسی می‌کند.
- سطح ۱ سازنده native مربوط به `Date` را جایگزین نمی‌کند و سبک‌ترین حالت است.
